## 描边与拟合修复的已有证据

这些是此前修复阶段的实测结果，并非本次新导入空工程生成的人物拟合结果。输入为同一参考图、Plum_kisekae 坐标、34 个有效标注、36 个优化键、同一组开始前权重、随机种子 `20240517` 和 5 个相同初值。每初值 15000 次上限，按实际总目标选择解，没有权重真值可用于验证照片恢复精度。

修复内容：同部位分段有序匹配；眼睛/嘴的上下弧分开；端点约束与有限弧长滑动；各部位等权；手动修改优先于历史描边；缺点回退到明确对应；候选探测不因细分密度改变；所有初值使用相同的开始前权重作为先验中心。模型轮廓是锚点折线近似，不是完整网格的可见轮廓。

设 `d_i` 为原图像素距离，`a_i` 为部位均衡对应权重且总和为 1，`K` 为优化键数，`w0_k` 为开始前权重，`w_k` 为 Unity 0–100 单位权重：

```text
z_i = d_i / 8
rho(z) = 0.5*z*z     (z <= 2)
         2*z - 2    (z > 2)
dataLoss = sum_i a_i*rho(z_i)
priorLoss = 0.25/K * sum_k 0.5*((w_k-w0_k)/25)^2
totalLoss = dataLoss + priorLoss
部位均衡二维偏差 = sqrt(sum_i a_i*d_i^2/2)
```

8 像素、25 分及 0.25 是测试前固定的工程尺度，不是测得的人脸分布。初值按 `totalLoss` 选择，二维偏差与先验分别展示。相机为固定正面正交投影加二维平移、缩放和 ±25° 平面旋转，不表示恢复真实焦距或三维转头。

同一固定评价相机、同一新轮廓指标的配对结果：

| 指标 | 旧算法 | 修复后 |
| --- | ---: | ---: |
| 达到 100 的权重数 | 17 | 1 |
| 位于 0 或 100 的权重数 | 33 | 20 |
| 平均权重 | 52.33 | 19.08 |
| 部位均衡二维偏差（原图像素） | 10.25237 | 11.14108 |
| 二维 Huber 损失 | 1.35319 | 1.39614 |

修复后先验代价 0.21136，总目标约 1.60750；未拟合模型的同口径偏差为 14.55 像素。旧算法原先的逐语义点 18.30 像素属于不同口径，不用于该表比较。

**修复以约 0.89 像素的同口径偏差增加换取较少的极端权重。** `eyelid_down` 仍达到 100，部分键的多初值差异仍明显。遮挡眼眉没有独立观测依据；不保证视觉更像。5 个初值不能证明全局最优，多初值跨度不是统计置信区间。

## 数据流、操作与依赖边界

手工流程在 Unity 内读取图片和坐标，计算结果并生成临时预览；点击应用才写模型权重，动画/存档操作会写工程资产。用户坐标和存档路径独立于插件代码。升级前仍需保存窗口中尚未持久化的标注与结果。

自动标点会启动用户配置的本地 Python 可执行文件，传递图片副本并读取 JSON；该路径应指向受信任环境。每任务临时图片/结果存于 `Library/PhotoAutoLandmarks`，不会自动清理。适配检测脚本不上传照片；安装依赖和下载权重会联网。二次元下载器固定作者仓库 revision 并核对 LFS SHA256，使用 safetensors。下载来源与操作见 [自动标点安装](自动标点安装.zh-CN.md)。

依赖锁不是漏洞扫描报告。基础卡片、二维码、PNG 与旧 FX 集成功能作为依赖保留，本次未对这些继承模块逐一开展安全或来源鉴定。原插件没有独立根级开源许可，本次不替权利人增加授权；详见 [来源与许可](来源与许可.zh-CN.md)。

## 尚未证明的能力

- 任意网格自动语义坐标正确、任何形态键都线性可用、任意 VRM/照片可靠还原。
- 单图鼻/嘴/下巴深度、遮挡部位、真实拍摄焦距与三维姿态的准确恢复。
- 其他 Unity 版本、macOS/Linux、URP/HDRP 与当前环境同等兼容。
- 新机器完整自动标点安装及推理必然成功；本包不带权重和运行环境。
- 自动坐标候选无需人工检查，或更低二维误差必然对应更真实的人脸。

本版本是针对指定模型和指定 landmark mapping 的原型，不构成任意 VRM 或任意真实照片都能可靠恢复的保证。
